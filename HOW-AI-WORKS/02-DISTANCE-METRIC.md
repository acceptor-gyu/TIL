# 거리 측정
> 대표적인 거리 측정: 코사인 유사도와 정규화, 함수 선택

## 코사인 유사도
크기는 무시하고 방향만 본다.

> 내적 공식에서 유도  
> a⋅b = ||a||*||b||*cosθ 를 양변을 ||a||*||b|| 로 나누면,  
> cosθ = (a⋅b) / (||a||*||b||)

## 세 가지 기준점
θ = 0° → cosθ = 1 → a와 b는 같은 방향, 유사도 최대  
θ = 90° → cosθ = 0 → a와 b는 직각, 방향 관계 없음  
θ = 180° → cosθ = -1 → a와 b는 반대 방향 , 유사도 최소

## 크기는 분모가 소거한다
분모 ||a||*||b||가 두 벡터의 크기를 나누어 없애 준다. 결과는 오직 θ  
즉 방향에만 달린다.
- 유클리드: 방향이 같아도 크기가 다르면 값이 달라진다.
- 코사인: 크기가 달라도 방향이 같으면 값이 같다.

`semantic search`에서 코사인 유사도를 볼 때, 값이 1에 가까우면 가깝다, 0에 가까우면 연관이 없다.

> e.g. a = [1, 1], b = [2, 2] (b는 a의 2배)  
> a⋅b = 4 ||a|| = √2, ||b|| = 2√2  
> cosθ = 4 / (√2 * 2√2) = 1 → a와 b는 같은 방향, 유사도 최대  
> 방향이 같기 때문에 크기 차이와 무관하게 값은 1
>
> a = [1, 0], b = [-1, 0] - 직각  
> a⋅b = 0   
> 내적이 0이면 분자가 0 -> 코사인 유사도도 0 
> 
> a = [1, 0], b = [-1, 0] - 반대 방향
> a⋅b = -1 ||a|| = 1, ||b|| = 1
> cosθ = -1 / (1 * 1) = -1


## 유클리드 거리와 코사인 유사도 중에 어떤 함수를 선택해야 할까?
벡터 데이터베이스에 대한 검색 관점

### 정규화 -> 분모가 1이 된다
두 벡터를 정규화하면 ||a|| = 1, ||b|| = 1  
cosθ = hat{a}⋅hat{b} / 1 * 1 = hat{a}⋅hat{b}  
정규화된 벡터에서 `코사인 유사도 == 내적`

> e.g. [3, 4] 정규화 -> [0.6, 0.8], b = [1, 0]  
> hat{a} ⋅ b = 0.6 * 1 + 0.8 * 0 = 0.6  
> cosθ = 0.6 / (1 * 1) = 0.6  
> 두 방법이 같은 값을 돌려준다.

>> 정규화된 벡터에서는 내적을 계산하는 것만으로도 코사인 유사도가 나온다!   
> 
> 대규모 검색처럼 수백만 번의 유사도를 반복 계산하는 환경에서는 `벡터를 미리 정규화`해서 저장해두고 `내적 연산만` 쓰면 된다.  
> 
> 정규화 비용은 벡터를 저장할 때 한 번만 계산하면 되므로, 최적화할 수 있다. (정규화하는 이유)


`텍스트 임베딩`(텍스트를 벡터로 바꾼 임베딩)에서는 `코사인 유사도`를 주로 사용한다.
- 임베딩에서는 `문장의 의미`가 주로 `벡터의 방향`에 담긴다.
- 벡터의 크기는 문장의 길이, 단어 수, 문장 구조 등의 영향을 많이 받는다.
- semantic search(의미 검색)에서는 문장의 의미가 중요하므로, 벡터의 크기보다는 방향이 더 중요하다.   
  -> semantic search에서는 주로 코사인 유사도를 사용한다.

### 유클리드 거리 vs 코사인 유사도
둘 다 두 벡터의 관계를 숫자로 표현하는 것이다.  
무엇을 측정하고 싶은 지가 기준이 된다.

- 의미를 비교하고 싶다면, 코사인 유사도 또는 정규화 후 내적 (방향 자체에 의미가 담기는 형식)
- 벡터의 크기 자체가 의미있는 경우는 유클리드 거리 (센서값, 좌표 데이터 등)

> 대부분의 경우 코사인 유사도를 사용한다. 센서값, 좌표 등의 도메인 영역은 특수한 경우일 것이다.
