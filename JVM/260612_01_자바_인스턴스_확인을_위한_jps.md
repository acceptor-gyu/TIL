# 자바 인스턴스 확인을 위한 jps

## 개요
현재 시스템에서 실행 중인 JVM(자바 프로세스) 인스턴스를 확인하기 위한 JDK 표준 도구인 `jps`(Java Virtual Machine Process Status Tool)에 대해 정리한다.

## 상세 내용

### jps란 무엇인가

`jps`는 `$JAVA_HOME/bin/` 디렉터리에 위치하는 JDK 번들 진단 도구다. 현재 시스템에서 **계측(instrumented)된 JVM 프로세스 목록**을 출력한다.

운영체제 수준의 `ps` 명령어와 비교하면 다음과 같은 차이가 있다.

| 항목 | ps | jps |
|---|---|---|
| 대상 | 모든 OS 프로세스 | JVM 프로세스만 |
| 정보 | PID, 명령어 경로 등 | LVMID, 메인 클래스명, JVM 옵션 등 |
| JVM 내부 정보 | 없음 | 클래스명, JVM 인자, main 인자 확인 가능 |
| 의존성 | OS 커널 | hsperfdata / jvmstat |

`jps`는 HotSpot JVM이 공유 메모리 파일(`hsperfdata`)에 기록하는 성능 카운터 정보를 읽어 JVM 프로세스를 탐지한다. OS `ps` 명령어는 JVM 내부 정보를 알 수 없지만, `jps`는 메인 클래스명·JVM 인자·메인 인자까지 한 번에 확인할 수 있다.

> 공식 문서에 "실험적(experimental)이며 지원되지 않는 도구"로 명시되어 있다. 미래 JDK 버전에서 변경 또는 제거될 수 있다.

### 기본 사용법

옵션 없이 실행하면 `LVMID`와 메인 클래스명(또는 JAR 파일명의 단축 형태)을 출력한다.

```bash
$ jps
18027 Java2Demo.JAR
18032 jps
18005 jstat
```

**LVMID(Local VM Identifier)**는 JVM 프로세스를 식별하는 로컬 식별자다. 일반적으로 OS PID와 동일하지만, 반드시 같다는 보장은 없다. 이 LVMID를 `jstat`, `jstack`, `jmap`, `jcmd` 등의 진단 도구에 전달해 상세 분석을 수행한다.

### 주요 옵션

```
jps [options] [hostid]
```

| 옵션 | 설명 |
|---|---|
| `-q` | LVMID만 출력 (클래스명, 인자 생략) |
| `-m` | `main` 메서드에 전달된 인자 출력 |
| `-l` | 패키지를 포함한 메인 클래스 전체 경로 또는 JAR 파일 전체 경로 출력 |
| `-v` | JVM에 전달된 인자(JVM 옵션) 출력 |
| `-V` | hsperfdata 기반으로 LVMID만 출력 (`-q`와 유사하지만 데이터 소스가 다름) |

옵션은 조합해서 사용할 수 있다. 진단 시 가장 유용한 조합은 `-lvm`이다.

```bash
# 클래스 전체 경로 + JVM 옵션 + main 인자를 모두 확인
$ jps -lvm

# LVMID만 뽑아서 스크립트에 활용
$ jps -q
```

**`-l` 사용 예시**

패키지 없는 단축 클래스명 대신 전체 경로가 출력되어, 동일한 이름의 클래스가 여러 프로세스로 떠 있을 때 구분이 쉽다.

```bash
$ jps -l
18027 /opt/jdk/demo/jfc/Java2D/Java2Demo.JAR
18005 sun.tools.jstat.Jstat
```

**`-v` 사용 예시**

JVM 힙 옵션이나 GC 설정 등 실제로 어떤 JVM 인자가 적용되어 기동되었는지 확인할 수 있다.

```bash
$ jps -v
18027 Java2Demo.JAR -Xms64m -Xmx512m -XX:+UseG1GC
```

### 원격 JVM 확인

원격 호스트의 JVM 프로세스를 조회하려면 대상 서버에서 `jstatd` 데몬이 실행 중이어야 한다. `jstatd`는 RMI 기반으로 hsperfdata 정보를 외부에 노출한다.

```bash
# 기본 RMI 포트(1099)로 원격 호스트 조회
$ jps remote.domain

# 비표준 포트 및 긴 이름으로 조회
$ jps -l remote.domain:2002
3002 /opt/jdk/demo/jfc/Java2D/Java2Demo.JAR
3102 sun.tools.jstatd.jstatd -p 2002
```

hostid 형식은 다음과 같다.

```
[protocol:][[//]hostname][:port][/servername]
```

- `protocol`: 통신 프로토콜 (기본값: 로컬 최적화 프로토콜, hostname 지정 시 `rmi`)
- `port`: 원격 서버 포트 (기본값: 1099)
- `servername`: RMI 원격 객체 이름

### 동작 메커니즘 상세

HotSpot JVM은 기동 시 `/tmp/hsperfdata_<user>/<pid>` 경로에 바이너리 파일을 생성한다. 이 파일은 공유 메모리(shared memory)를 통해 외부 프로세스와 연결되며, `jps`는 이 파일 목록을 순회해 실행 중인 JVM 인스턴스를 탐지한다.

```
/tmp/hsperfdata_luke/
├── 18027   ← Java2Demo 프로세스 PID
├── 18005   ← jstat 프로세스 PID
```

파일은 공유 메모리를 통해 접근하기 때문에 **폴링 오버헤드가 매우 낮다.** 프로세스가 종료되면 파일도 자동으로 삭제된다.

**탐지 실패 케이스**

`-XX:-UsePerfData` JVM 옵션이 활성화된 경우, JVM은 hsperfdata 파일을 생성하지 않는다. 이 경우 `jps`는 해당 JVM 프로세스를 탐지하지 못한다.

```bash
# 이 옵션으로 기동된 JVM은 jps 목록에 나타나지 않음
java -XX:-UsePerfData -jar myapp.jar
```

**컨테이너(Docker) 환경**

Docker는 PID 네임스페이스(namespace) 격리를 사용한다. 컨테이너 내부의 JVM 프로세스는 호스트와 별도의 PID 네임스페이스를 가지므로, **호스트에서 실행한 `jps`는 컨테이너 내부의 JVM 프로세스를 탐지하지 못한다.** 반대로, 컨테이너 내부에서 실행한 `jps`는 컨테이너 내 JVM 프로세스만 보인다.

### 다른 진단 도구와의 연계

`jps`로 LVMID를 식별한 후 다른 진단 도구에 전달하는 것이 일반적인 진단 흐름이다.

```bash
# 1. 대상 JVM LVMID 확인
$ jps -l
12345 com.example.MyApplication

# 2. GC 통계 모니터링
$ jstat -gcutil 12345 1000

# 3. 스레드 덤프
$ jstack 12345

# 4. 힙 덤프
$ jmap -dump:format=b,file=heap.hprof 12345

# 5. 종합 진단 (jcmd 권장)
$ jcmd 12345 VM.info
$ jcmd 12345 GC.run
```

`jcmd`는 `jps`의 기능을 포함하면서 더 다양한 진단 명령을 지원하는 상위 도구다. `jps`를 대체하는 용도로도 사용할 수 있다.

```bash
# jcmd로 실행 중인 JVM 목록 확인 (jps -l과 유사)
$ jcmd -l
```

## 핵심 정리
- `jps`는 로컬에서 실행 중인 JVM 인스턴스를 빠르게 식별하는 도구다
- 출력되는 식별자는 LVMID이며 일반적으로 OS PID와 동일하다
- `-l`, `-v`, `-m` 조합으로 클래스/옵션/인자를 함께 파악할 수 있다
- `jps`는 hsperfdata에 의존하므로 `-XX:-UsePerfData` 환경에서는 보이지 않는다
- 공식적으로 "실험적·비지원" 도구로 분류되며, 상황에 따라 `jcmd -l`로 대체 가능하다

## 기술적 한계와 보완 전략

| 한계 | 원인 | 보완 방법 |
|---|---|---|
| 프로세스 미탐지 | `-XX:-UsePerfData` 옵션 | `ps aux \| grep java` 또는 `jcmd` |
| 컨테이너 내 프로세스 미탐지 | Docker PID 네임스페이스 격리 | 컨테이너 내부에서 직접 `jps` 실행 또는 `docker exec` 활용 |
| 타 사용자 프로세스 미탐지 | 파일 접근 권한 | `sudo jps` (단, 환경에 따라 JAVA_HOME 차이 주의) |
| 출력 형식 변경 가능성 | 비공식 도구 특성 | 스크립트 파싱 지양, `jcmd` 사용 권장 |

## 키워드

| 키워드 | 설명 |
|---|---|
| **jps** | JDK에 포함된 JVM 프로세스 상태 도구. 현재 시스템에서 실행 중인 JVM 인스턴스의 LVMID와 클래스명을 출력한다. |
| **JVM** | Java Virtual Machine. 자바 바이트코드를 실행하는 가상 머신. `jps`는 JVM 프로세스에 특화된 탐지 도구다. |
| **LVMID** | Local VM Identifier. jps가 JVM 프로세스를 식별하는 로컬 식별자. 보통 OS PID와 동일하지만 반드시 같지는 않다. |
| **hsperfdata** | HotSpot JVM이 `/tmp/hsperfdata_<user>/<pid>` 경로에 생성하는 공유 메모리 기반 성능 데이터 파일. jps와 jstat의 데이터 소스다. |
| **jvmstat** | HotSpot 내부의 성능 카운터 수집 프레임워크. hsperfdata 파일에 데이터를 기록하며 외부 도구가 이를 폴링한다. |
| **JDK 진단 도구** | jps, jstat, jstack, jmap, jcmd 등 JDK에 포함된 JVM 분석 도구 모음. jps는 대상 프로세스 식별의 첫 단계로 활용된다. |
| **jstatd** | RMI 기반 데몬 프로세스. 원격 호스트에서 실행하면 외부에서 jps/jstat으로 해당 호스트의 JVM 프로세스를 조회할 수 있다. |
| **jcmd** | JDK 7 이후 도입된 종합 진단 도구. jps보다 넓은 기능을 제공하며, `jcmd -l`로 jps의 기본 기능을 대체할 수 있다. |
| **UsePerfData** | `-XX:-UsePerfData` 옵션으로 비활성화 시 hsperfdata 파일이 생성되지 않아 jps 탐지에서 제외된다. |
| **프로세스 모니터링** | 운영 중인 JVM의 상태를 지속적으로 확인하는 활동. jps는 프로세스 식별 단계, jstat/jstack/jmap은 상세 분석 단계에서 사용된다. |
