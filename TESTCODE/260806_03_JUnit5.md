# JUnit5

## 개요
JUnit5(Jupiter)는 JUnit Platform, JUnit Jupiter, JUnit Vintage 세 개의 서브 프로젝트로 구성된 테스트 프레임워크다. Java 8 이상의 람다식을 적극 활용해 함수형 프로그래밍 스타일로 테스트를 작성할 수 있으며, 파라미터화 테스트, 동적 테스트, 확장 모델 등 JUnit4에서 제공하지 않던 기능들을 새롭게 제공한다.

## 상세 내용

### 1. JUnit5의 아키텍처
JUnit5는 단일 jar가 아니라 3개의 하위 프로젝트로 분리되어 있다.

- **JUnit Platform**: JVM에서 테스트 프레임워크를 실행하기 위한 기반(Foundation) 역할을 한다. 테스트를 실행할 프레임워크를 개발하기 위한 `TestEngine` API를 정의하고, 커맨드라인에서 플랫폼을 실행하는 Console Launcher, Gradle/Maven 빌드 플러그인 등을 제공한다.
- **JUnit Jupiter**: JUnit5의 테스트/확장을 작성하기 위한 프로그래밍 모델과 확장 모델의 조합이다. Jupiter 하위 프로젝트는 플랫폼에서 Jupiter 기반 테스트를 실행하는 `TestEngine`을 제공한다.
- **JUnit Vintage**: 하위 호환성을 위해 JUnit3, JUnit4 기반 테스트를 플랫폼 위에서 실행하는 `TestEngine`을 제공한다. classpath 또는 module path에 JUnit 4.12 이상이 있어야 한다.

```
JUnit 5 = JUnit Platform + JUnit Jupiter + JUnit Vintage
```

`TestEngine`은 `Launcher`에 의해 검색·실행되며, IDE나 빌드 도구는 `Launcher API`를 통해 플랫폼과 상호작용한다. 즉 IDE/빌드 도구는 어떤 `TestEngine`이 붙어 있는지 몰라도 통일된 방식으로 테스트를 실행할 수 있다. 이 구조 덕분에 JUnit4 테스트와 JUnit5 테스트를 같은 프로젝트, 같은 실행 파이프라인에서 동시에 돌릴 수 있다.

### 2. 기본 어노테이션
- `@Test`: 테스트 메서드임을 나타낸다. JUnit4와 달리 `public`이 아니어도 되며, 예외를 던지는 `expected` 속성이 사라지고 `assertThrows`로 대체되었다.
- `@DisplayName`: 테스트 클래스/메서드에 표시할 커스텀 이름을 지정한다. 리포트나 IDE에 노출된다.
- 생명주기 콜백
  - `@BeforeEach` / `@AfterEach`: 각 테스트 메서드 실행 전/후 호출 (JUnit4의 `@Before`/`@After` 대체)
  - `@BeforeAll` / `@AfterAll`: 클래스 내 모든 테스트 실행 전/후 1회 호출 (JUnit4의 `@BeforeClass`/`@AfterClass` 대체). 기본 인스턴스 생명주기(`PER_METHOD`)에서는 `static` 메서드여야 한다.
- `@Disabled`: 특정 테스트를 실행에서 제외한다 (JUnit4의 `@Ignore` 대체).
- `@Tag`: 테스트를 태깅해서 특정 태그만 선택적으로 실행할 수 있게 한다 (Maven/Gradle의 groups/categories 기능과 연동).
- `@Nested`: static이 아닌 내부 클래스에 붙여 계층적으로 테스트를 그룹화한다. 관련된 시나리오를 묶어서 표현할 때 유용하다.

### 3. Assertions
JUnit Jupiter는 `org.junit.jupiter.api.Assertions` 클래스의 정적 메서드로 assertion을 제공한다.

- `assertEquals(expected, actual)`, `assertTrue(condition)`, `assertNotNull(obj)` 등 기본 검증 메서드
- `assertThrows(ExpectedException.class, executable)`: 예외 발생을 검증하고, 발생한 예외 객체를 반환받아 메시지 등을 추가로 검증할 수 있다.
- `assertAll(executables...)`: 여러 assertion을 그룹으로 묶어 실행하고, 중간에 실패해도 나머지 assertion을 모두 실행한 뒤 실패 목록을 한 번에 리포트한다 (soft assertion과 유사).
- `assertTimeout(Duration, executable)` / `assertTimeoutPreemptively`: 특정 시간 안에 실행이 끝나는지 검증한다. `Preemptively`는 타임아웃 초과 시 별도 스레드에서 즉시 중단시킨다.
- 대부분의 assertion은 람다를 인자로 받아 실패 메시지를 지연 평가(lazy evaluation)할 수 있다.
- 필요하면 AssertJ, Hamcrest 같은 서드파티 assertion 라이브러리와 조합해서 더 풍부한 matcher 문법을 사용할 수 있다.

### 4. Assumptions
`org.junit.jupiter.api.Assumptions`를 통해 특정 조건이 만족될 때만 테스트를 계속 진행하도록 만들 수 있다.

- `assumeTrue(condition)`: 조건이 거짓이면 테스트를 즉시 중단(실패가 아닌 abort)한다.
- `assumingThat(condition, executable)`: 조건이 참일 때만 주어진 코드 블록을 실행하고, 조건이 거짓이면 나머지 테스트는 계속 진행된다.
- 특정 환경(OS, CI 여부 등)에서만 의미 있는 테스트를 조건부로 실행할 때 사용한다.

### 5. 파라미터화 테스트
`@ParameterizedTest`는 하나의 테스트 메서드를 여러 입력 조합으로 반복 실행할 수 있게 한다. 소스 어노테이션 없이 `@ParameterizedTest`만 사용하면 설정 오류로 런타임에 실패한다.

- `@ValueSource`: 단일 타입의 리터럴 배열(int, long, double, String 등)을 제공한다.
- `@CsvSource`: `"2, 3, 5"`처럼 콤마로 구분된 여러 컬럼 값을 인라인으로 제공한다.
  ```java
  @ParameterizedTest
  @CsvSource({ "2, 3, 5", "4, 5, 9", "10, 15, 25" })
  void testAddition(int a, int b, int expected) {
      assertEquals(expected, a + b);
  }
  ```
- `@MethodSource`: 정적 팩토리 메서드가 반환하는 `Stream`/`Collection`/`Iterable`/배열을 인자로 사용한다. 임의의 객체를 넘길 수 있어 가장 유연하다.
  ```java
  static List<String> asia() {
      return List.of("Japan", "India", "Thailand");
  }

  @ParameterizedTest
  @MethodSource("asia")
  void countryNameLongerThanThree(String country) {
      assertTrue(country.length() > 3);
  }
  ```
- `@EnumSource`: enum 상수 전체 또는 일부를 인자로 제공한다.
- `@CsvFileSource`: CSV 파일에서 데이터를 읽어온다.

### 6. 동적 테스트와 반복 테스트
- `@RepeatedTest(n)`: 동일한 테스트를 n번 반복 실행한다. `RepetitionInfo`를 주입받아 현재 반복 횟수를 확인할 수 있다.
- `@TestFactory`와 `DynamicTest`: 컴파일 타임에 테스트 개수가 고정되지 않고, 런타임에 프로그래밍적으로 테스트를 생성해야 할 때 사용한다. `@TestFactory` 메서드는 `Stream<DynamicTest>` 또는 `Collection<DynamicTest>`를 반환하며, 각 `DynamicTest`는 표시 이름과 실행 로직(`Executable`)의 쌍으로 구성된다.

### 7. 확장 모델 (Extension Model)
JUnit5는 JUnit4의 `Runner`, `TestRule`, `MethodRule` 세 가지 확장 지점을 `Extension`이라는 단일 개념으로 통합했다.

- `@ExtendWith(MyExtension.class)`로 확장을 등록한다.
- `Extension`은 마커 인터페이스이며, 실제 동작은 `BeforeEachCallback`, `AfterEachCallback`, `ParameterResolver`, `TestInstancePostProcessor` 등 세부 인터페이스를 구현해 정의한다.
- 여러 확장을 조합해서 사용할 수 있고, 확장끼리 순서를 제어할 수도 있다.
- Mockito(`MockitoExtension`), Spring(`SpringExtension`) 등 대부분의 서드파티 테스트 통합 라이브러리가 이 확장 모델을 기반으로 동작한다. 예를 들어 Spring Boot 테스트의 `@SpringBootTest`는 내부적으로 `@ExtendWith(SpringExtension.class)`를 메타 어노테이션으로 포함한다.

### 8. 테스트 인스턴스 생명주기
- 기본값은 `TestInstance.Lifecycle.PER_METHOD`로, 테스트 메서드마다 새로운 테스트 클래스 인스턴스를 생성한다. 이 때문에 `@BeforeAll`/`@AfterAll`은 인스턴스 상태에 접근할 수 없어 `static`이어야 한다.
- `@TestInstance(Lifecycle.PER_CLASS)`를 클래스에 붙이면 클래스당 인스턴스를 하나만 생성해서 모든 테스트가 공유한다. 이 모드에서는 `@BeforeAll`/`@AfterAll`을 `static`으로 선언하지 않아도 되고, 인스턴스 필드를 테스트 간 상태 공유용으로 쓸 수 있다. 단, 테스트 간 상태 격리가 깨질 위험이 있으므로 신중하게 사용해야 한다.

## 핵심 정리
- JUnit5는 Platform/Jupiter/Vintage로 모듈이 분리되어 있어, `TestEngine` 확장을 통해 다른 테스트 프레임워크(Kotest 등)도 같은 Launcher 인프라 위에서 실행할 수 있다.
- `assertThrows`, `assertAll`, 람다 기반 assertion으로 JUnit4보다 표현력이 풍부해졌고, `assumeTrue`/`assumingThat`으로 조건부 실행이 가능해졌다.
- `@ParameterizedTest` + `@MethodSource`/`@CsvSource`/`@ValueSource`/`@EnumSource` 조합으로 중복되는 테스트 코드를 크게 줄일 수 있다.
- `Extension` 모델은 JUnit4의 분산된 확장 지점(Runner/Rule)을 단일 인터페이스 계열로 통합했고, Spring·Mockito 등 대부분의 통합 라이브러리가 이를 기반으로 동작한다.
- 테스트 인스턴스 생명주기(`PER_METHOD` vs `PER_CLASS`)는 `@BeforeAll`/`@AfterAll`을 static으로 강제할지 여부와 테스트 간 상태 공유 가능 여부를 결정한다.

## 기술적 한계와 보완 전략
- **`PER_CLASS` 생명주기의 상태 오염 위험**: 인스턴스를 공유하면 테스트 순서에 따라 결과가 달라질 수 있다. 필드 초기화를 `@BeforeEach`에서 명시적으로 리셋하거나, 기본값인 `PER_METHOD`를 유지하는 편이 안전하다.
- **`assertTimeoutPreemptively`의 스레드 안전성 문제**: 별도 스레드에서 실행을 중단시키기 때문에 테스트 대상 코드가 스레드 로컬이나 트랜잭션 컨텍스트에 의존하면 예상치 못한 부작용이 발생할 수 있다. 가능하면 `assertTimeout`(중단 없이 시간만 측정)을 우선 고려한다.
- **JUnit Vintage의 유지보수 부담**: Vintage 엔진은 레거시 JUnit4 테스트를 실행하기 위한 다리 역할일 뿐, 신규 기능(파라미터화 테스트, 동적 테스트 등)을 제공하지 않는다. 장기적으로는 Jupiter로 마이그레이션하는 것이 바람직하다.
- **파라미터화 테스트의 디버깅 어려움**: 여러 케이스가 한 메서드에서 실행되므로 실패 케이스를 특정하기 어려울 수 있다. `@CsvSource`에 의미 있는 이름을 붙이거나 `@ParameterizedTest(name = "...")`로 표시 이름을 커스터마이징하면 리포트 가독성이 좋아진다.

## 키워드
- **JUnit5**: Java 진영의 대표적인 테스트 프레임워크로, Platform/Jupiter/Vintage 세 모듈로 구성된 5세대 JUnit.
- **Jupiter**: JUnit5에서 실제 테스트 작성에 사용하는 프로그래밍 모델·확장 모델을 제공하는 하위 프로젝트.
- **TestEngine**: JUnit Platform 위에서 특정 프로그래밍 모델의 테스트를 발견하고 실행하는 SPI(Service Provider Interface).
- **Assertions**: 테스트 결과가 기대값과 일치하는지 검증하는 정적 메서드 모음(`assertEquals`, `assertThrows` 등).
- **ParameterizedTest**: 하나의 테스트 메서드를 여러 입력값으로 반복 실행하게 해주는 어노테이션.
- **Extension Model**: JUnit4의 Runner/Rule을 대체하는 단일 확장 인터페이스 체계로, `@ExtendWith`로 등록한다.
- **Lifecycle**: 테스트 클래스 인스턴스를 매 메서드마다 생성할지(`PER_METHOD`), 클래스당 하나만 생성할지(`PER_CLASS`) 결정하는 설정.
- **Assumptions**: 특정 조건이 충족될 때만 테스트를 계속 진행하도록 하는 API(`assumeTrue`, `assumingThat`).
- **DynamicTest**: 런타임에 프로그래밍적으로 생성되는 테스트 케이스로, `@TestFactory`와 함께 사용된다.
- **Nested**: 내부 클래스를 이용해 관련 테스트를 계층적으로 그룹화하는 어노테이션.
