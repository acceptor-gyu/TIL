# hermes agent

## 개요

Hermes Agent는 Nous Research가 2026년 2월 25일 공개한 오픈소스 자율 AI 에이전트 프레임워크다. 메신저 신 헤르메스(Hermes)처럼 다양한 플랫폼 간 메시지를 매개하고, 경험을 통해 스스로 성장한다는 컨셉을 담고 있다. 출시 7주 만에 GitHub 스타 95,000개를 돌파하며 AI 에이전트 생태계에서 빠르게 주목받고 있다.

기존 에이전트 프레임워크들이 매 세션을 독립적으로 처리하는 것과 달리, Hermes Agent는 내장된 학습 루프를 통해 경험에서 스킬을 생성하고 세션이 끊겨도 기억과 스킬을 유지한다. "The agent that grows with you"라는 슬로건이 이 특성을 잘 표현한다.

## 상세 내용

### hermes agent란

Hermes Agent는 단순한 에이전트 프레임워크를 넘어 **자가 학습형 개인 에이전트 런타임**이다. 핵심 컨셉은 세 가지다.

- **영구 기억(Persistent Memory)**: 세션 간 사용자 프로필, 대화 이력, 선호도를 유지한다.
- **자동 스킬 생성(Skill Automation)**: 복잡한 작업을 수행한 후 재사용 가능한 스킬 파일을 자동으로 만든다.
- **자기 개선(Self-Improvement)**: 사용할수록 성능이 좋아지는 닫힌 피드백 루프를 가진다.

이름의 유래인 헤르메스는 올림포스 12신 중 전령(메신저)의 신으로, 신과 인간 사이를 오가며 메시지를 전달한다. Hermes Agent 역시 사용자와 다양한 플랫폼, 다양한 LLM 사이에서 메시지를 중개하고 라우팅하는 역할을 메타포로 삼는다.

### 아키텍처 구조

#### 핵심 컴포넌트

```
┌────────────────────────────────────────────────────────────┐
│               진입점 (Entry Points)                        │
│   CLI Session │ Gateway (Telegram/Discord/Slack 등) │ ACP  │
└───────────────────────────┬────────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────────┐
│              AIAgent (run_agent.py)                        │
│  - 약 13,700줄의 중앙 대화 루프 조율 엔진                  │
│  - 프롬프트 구성, 도구 실행, 메모리 관리                   │
└──────────┬───────────────┬───────────────┬─────────────────┘
           │               │               │
           ▼               ▼               ▼
     프롬프트 시스템    도구 시스템    공급자 해결(Provider)
  (성격+메모리+스킬)  (61개 도구,    (18개+ LLM 공급자
                     52개 툴셋)      통합 런타임)
```

**프롬프트 시스템**: 시스템 프롬프트는 성격 정의, 메모리, 스킬, 컨텍스트 파일을 동적으로 조합하여 구성된다. 대화 턴이 임계값을 초과하면 자동으로 요약하고, Anthropic 캐시 브레이크포인트를 적용해 토큰 비용을 절감한다.

**도구 시스템**: 중앙 레지스트리에 52개 툴셋 내 61개 도구가 등록되어 있다. 각 도구 파일은 임포트 시점에 자동 등록되며 MCP(Model Context Protocol)를 통해 외부 도구도 연결할 수 있다.

**공급자 해결**: `(provider, model)` 튜플을 `(api_mode, api_key, base_url)`로 매핑하는 공유 런타임 해석기가 18개 이상의 LLM 공급자를 지원한다(Nous Portal, OpenRouter, NVIDIA NIM 등).

#### 메시지 라우팅 / 통신 흐름

세 가지 경로로 메시지가 흐른다.

| 경로 | 흐름 |
|------|------|
| CLI 세션 | 사용자 입력 → 프롬프트 구성 → API 호출 → 도구 실행 루프 → 응답 저장 |
| Gateway 메시지 | 플랫폼 이벤트 → 어댑터 → GatewayRunner → 세션 생성 → AIAgent 실행 → 응답 전달 |
| Cron 작업 | 스케줄러 → 작업 로드 → 새 AIAgent(히스토리 미포함) → 응답 전달 |

단일 AIAgent 엔진이 세 경로를 모두 처리하는 **플랫폼 독립성**이 특징이다.

#### 모델 통합 방식

코드 변경 없이 `hermes model` 명령 하나로 모델을 전환할 수 있다. Hermes 3 기반 모델은 `<tool_call>` XML 포맷으로 구조화된 도구 호출을 생성하도록 특별히 파인튜닝되어 있어 8B 가중치에서도 일관된 JSON 인자를 생성한다.

### 주요 기능

#### Tool Use 방식

도구는 타입 힌트와 독스트링이 있는 Python 함수로 정의한다. 프레임워크가 이 시그니처를 읽어 모델에 사용 가능한 도구 목록과 호출 방법을 전달한다.

```python
def get_weather(city: str, units: str = "celsius") -> dict:
    """
    특정 도시의 현재 날씨를 반환한다.
    
    Args:
        city: 날씨를 조회할 도시 이름
        units: 온도 단위 (celsius 또는 fahrenheit)
    """
    ...
```

#### Function Calling 패턴

Hermes 3은 `<tool_call>` XML 형식으로 도구 호출을 구조화한다.

```
1. LLM이 작업을 받음
2. <tool_call> 태그로 함수명 + JSON 인자 출력
3. 코드가 해당 함수 실행
4. 결과를 컨텍스트에 추가
5. 충분한 정보가 쌓이면 최종 답변 출력 (tool_call 없음 → 루프 종료)
```

로컬에서 Ollama로 실행한 Hermes 3 8B가 GPT-4o 기반 LangGraph와 불과 3%p 차이인 91% 도구 호출 정확도를 보인다.

#### 시스템 프롬프트 / 컨텍스트 관리

**설계 원칙**:
- **프롬프트 안정성**: 대화 중 시스템 프롬프트는 불변으로 유지된다.
- **관찰 가능성**: 모든 도구 호출 내용이 사용자에게 표시된다.
- **중단 가능성**: API 호출과 도구 실행을 언제든지 중단할 수 있다.

### 활용 사례

#### 멀티 에이전트 환경에서의 활용

Hermes 3 기반 멀티 에이전트 구성은 세 레이어로 역할을 분리한다.

```
오케스트레이터 (도구 없음, JSON 계획 출력)
        │
        ├── 전문가 서브에이전트 A (스코프된 툴셋 1개)
        ├── 전문가 서브에이전트 B (스코프된 툴셋 1개)
        └── 전문가 서브에이전트 C (스코프된 툴셋 1개)
                          │
                    합성 패스 (결과 통합 → 최종 답변)
```

복잡한 작업을 분리해 병렬 실행하고, 결과를 자동으로 통합한다.

#### 에이전트 간 메시지 전달 구조

격리된 서브에이전트를 생성해 병렬 작업을 처리하며, Python 스크립트로 RPC를 통해 도구를 호출할 수 있다. 각 서브에이전트는 독립된 메모리와 툴셋, 역할을 가진다.

#### 실제 프로덕션 적용 예시

- **개인 비서**: Telegram/Discord/Slack 등 메시징 앱에 연결해 음성 메모 전사, 크로스 플랫폼 대화 연속성 제공
- **자동화 파이프라인**: 일일 보고서 생성, 야간 백업 등 무인 Cron 작업 실행
- **코드 작업 자동화**: 코드베이스를 학습한 후 반복 작업을 스킬로 저장하고 재사용

### 다른 에이전트 프레임워크와의 비교

#### Claude Skills, SubAgent와의 차이

| 항목 | Hermes Agent | Claude Code SubAgent |
|------|-------------|---------------------|
| 모델 | 모델 무관 (18개+ 공급자) | Claude 모델 전용 |
| 기억 | 세션 간 영구 유지 | 세션 내 컨텍스트 |
| 스킬 생성 | 자동 생성 및 자기 개선 | 외부에서 정의 (CLAUDE.md) |
| 배포 | VPS/서버리스 등 독립 배포 | Claude Code 환경 의존 |
| 오픈소스 | 완전 오픈소스 | 독점 |

#### LangChain, AutoGen 등과 비교

| 항목 | Hermes Agent | LangChain/LangGraph | AutoGen (AG2) |
|------|-------------|---------------------|--------------|
| 핵심 강점 | 자기 개선, 영구 메모리 | 구조화된 워크플로우, 높은 프로덕션 성숙도 | 다중 에이전트 대화 정제 |
| 메모리 | SQLite + FTS5 영구 저장 | 외부 메모리 플러그인 필요 | 세션 단위 대화 히스토리 |
| 학습 루프 | 내장 (자동 스킬 생성) | 없음 | 없음 |
| 로컬 실행 | Ollama로 완전 로컬 지원 | 모델 무관 | 모델 무관 |
| 모니터링 | 기본 관찰 가능성 | LangSmith (성숙한 툴링) | 기본 로깅 |
| 학습 곡선 | 낮음 (CLI 즉시 사용) | 높음 (코드 작성 필요) | 중간 |

LangGraph와 Hermes Agent는 상호 배타적이지 않다. LangGraph는 ChatOllama 래퍼로 Hermes 3 모델을 수용하므로, 로컬에서 Hermes로 시작 후 상태 지속이 필요해지면 LangGraph로 마이그레이션하는 조합도 유효하다.

## 핵심 정리

- **핵심 포인트 1: Hermes Agent의 차별화 포인트** — 사용할수록 성능이 향상되는 내장 학습 루프. 경험에서 스킬을 자동 생성하고, SQLite+FTS5 기반 영구 메모리로 세션이 끊겨도 컨텍스트가 유지된다. 다른 에이전트 프레임워크에는 없는 시간 복리 효과(time compounding)가 가장 큰 차별점이다.

- **핵심 포인트 2: 메시지 전달 / 라우팅 구조** — CLI, Gateway(Telegram/Discord 등), ACP 세 진입점이 단일 AIAgent 엔진으로 수렴하는 구조. 18개 이상의 LLM 공급자를 통합 런타임으로 추상화하여 모델 교체가 코드 변경 없이 가능하다.

- **핵심 포인트 3: 적합한 사용 케이스** — 반복 작업이 많고 장기적으로 운영되는 개인 에이전트 또는 자동화 파이프라인에 가장 적합하다. 단발성 태스크나 엄격한 워크플로우 제어가 필요한 경우에는 LangGraph 같은 그래프 기반 프레임워크가 더 나은 선택일 수 있다.

## 기술적 한계와 보완 전략

### 한계점

1. **성숙도 부족**: 2026년 2월 출시되어 아직 초기 단계. LangGraph처럼 LangSmith 수준의 성숙한 관찰 가능성 툴링이 없다.
2. **단일 진입점 병목**: AIAgent 중앙 엔진(약 13,700줄)이 모든 진입점을 처리하므로, 초대형 배포 환경에서 병목이 될 수 있다.
3. **스킬 품질 보장 어려움**: 자동 생성된 스킬의 정확성을 외부에서 검증하기 어렵고, 잘못된 스킬이 쌓이면 오히려 성능이 저하될 수 있다.
4. **컨텍스트 윈도우 한계**: 학습 데이터와 메모리가 축적될수록 토큰 압박이 증가한다(캐시 최적화로 부분 완화).

### 대응 전략 / 보완 패턴

1. **점진적 스킬 검토**: `hermes skills list` 로 정기적으로 스킬 라이브러리를 점검하고 오래된 스킬을 정리한다.
2. **LangSmith 연동**: Hermes 3 모델을 LangGraph + LangSmith와 조합해 관찰 가능성을 확보한다.
3. **서브에이전트 격리**: 위험하거나 실험적인 작업은 격리된 서브에이전트에서 실행해 메인 에이전트 메모리를 오염시키지 않는다.
4. **토큰 비용 관리**: 스킬 3단계 점진적 로딩(20토큰 → 200토큰 → 1,000+토큰)을 활용하고, 캐시 브레이크포인트 설정을 튜닝한다.

## 키워드

### hermes agent
Nous Research가 2026년 2월 출시한 오픈소스 자율 AI 에이전트. 내장 학습 루프로 경험에서 스킬을 자동 생성하고, SQLite 기반 영구 메모리로 세션 간 기억을 유지한다. "$5 VPS에서 실행 가능한 자가 학습 에이전트"를 지향한다.

### AI Agent
주어진 목표를 달성하기 위해 환경을 인식하고, 도구를 사용하며, 스스로 판단·행동하는 소프트웨어 시스템. LLM을 두뇌로 삼아 계획 수립 → 도구 호출 → 결과 평가 → 재계획 사이클을 반복한다.

### Multi-Agent
여러 에이전트가 협력하여 하나의 복잡한 작업을 수행하는 패턴. 오케스트레이터가 JSON 계획을 세우고, 각 전문가 서브에이전트가 스코프된 툴셋으로 병렬 실행한 뒤 합성 패스에서 결과를 통합한다.

### Tool Use
LLM이 외부 함수, API, 데이터베이스 등을 호출하여 자신의 능력 범위를 확장하는 방식. 모델이 직접 실행하지 않고 "이 함수를 이 인자로 호출하라"는 구조화된 명령을 출력하면 런타임이 실행한다.

### Function Calling
LLM이 특정 함수를 호출하기 위해 구조화된 JSON을 생성하는 능력. Hermes 3은 `<tool_call>` XML 포맷으로 일관된 JSON 인자를 생성하도록 파인튜닝되어 있다. 8B 모델에서도 91% 정확도를 달성한다.

### Agent Routing
에이전트 시스템에서 들어오는 요청을 적절한 서브에이전트나 툴셋으로 분배하는 메커니즘. Hermes Agent는 CLI, Gateway, Cron 세 경로를 단일 AIAgent 엔진으로 수렴시키는 중앙 라우팅 구조를 사용한다.

### LLM Orchestration
여러 LLM 호출, 도구 실행, 메모리 조회를 조율하여 복잡한 작업을 완수하는 상위 제어 로직. Hermes Agent의 AIAgent 엔진(run_agent.py)이 이 역할을 담당하며 프롬프트 구성 → API 호출 → 도구 실행 → 결과 저장 루프를 관리한다.

### Message Passing
에이전트 시스템에서 구성 요소 간 정보를 전달하는 통신 방식. Hermes Agent는 플랫폼 이벤트를 어댑터 → GatewayRunner → AIAgent 체인으로 전달하고, 서브에이전트 간에는 RPC 방식으로 메시지를 주고받는다.

### Agent Framework
AI 에이전트를 구축하고 실행하기 위한 표준화된 도구, 라이브러리, 패턴의 집합. LangChain, AutoGen, CrewAI, Hermes Agent 등이 대표적이며, 각 프레임워크는 메모리 관리, 도구 등록, 멀티에이전트 조율 방식에서 서로 다른 철학을 가진다.

### Harness Architecture
오케스트레이터가 서브에이전트를 제어하고 조율하는 상위 설계 구조. Hermes Agent의 멀티에이전트 설계는 오케스트레이터(계획) → 전문가 서브에이전트(실행) → 합성 패스(통합)의 3단계 하네스 구조를 따른다.
