# SAP ERP 개발자란

## 개요
일반적으로 "개발자"라고 하면 웹/앱 서비스를 만드는 백엔드·프론트엔드 개발자를 떠올리지만, 국내외 대기업 IT 시장에는 이와는 다른 성격의 큰 축인 **SAP ERP 개발자(주로 ABAP 개발자)** 시장이 존재한다. SAP ERP 개발자는 회사의 회계, 물류, 인사, 생산 등 핵심 업무 프로세스를 담당하는 SAP 시스템을 커스터마이징·확장·연동하는 역할을 하며, 일반 웹 개발과는 기술 스택뿐 아니라 일하는 방식과 시장 구조 자체가 다르다.

## 상세 내용

### SAP와 ERP의 기본 개념
- **ERP(Enterprise Resource Planning, 전사적 자원 관리)**: 회계(재무), 인사, 생산, 물류, 영업 등 기업의 모든 업무 프로세스와 데이터를 하나의 통합된 시스템에서 관리하는 소프트웨어 체계. 부서별로 흩어져 있던 데이터를 하나의 DB와 프로세스로 묶어 실시간으로 정보를 공유하는 것이 핵심 목표.
- **SAP(Systeme, Anwendungen und Produkte in der Datenverarbeitung)**: 1972년 독일에서 설립된 회사로, 전 세계 ERP 시장 점유율 1위 업체. 포춘 500대 기업의 대다수, 그리고 국내 대기업(삼성, LG, SK 등)의 계열사 다수가 SAP를 기간계 시스템으로 채택하고 있다.
- **제품 라인**
  - **SAP ECC(ERP Central Component)**: 전통적인 온프레미스 SAP ERP. 2027년(연장 시 2030년)까지 표준 유지보수가 종료될 예정이라 S/4HANA로의 전환(Conversion) 프로젝트가 활발히 진행 중.
  - **SAP S/4HANA**: SAP HANA 인메모리 DB를 기반으로 한 차세대 ERP. On-Premise, Private Cloud, Public Cloud(SAP S/4HANA Cloud) 등 여러 배포 형태 존재.
- SAP는 특정 산업(제조, 화학, 유통, 공공 등)에 특화된 산업 솔루션(Industry Solution)도 함께 제공하며, 폐쇄적인 라이선스 기반 생태계 위에서 SI(시스템 통합)·컨설팅사가 프로젝트를 수행하는 구조가 일반적이다.

### SAP ERP 개발자의 역할
- SAP 프로젝트는 크게 **기능 컨설턴트(Functional Consultant)**와 **기술 개발자(Technical/ABAP Developer)**로 역할이 나뉜다.
  - 기능 컨설턴트: 고객의 업무 프로세스를 분석하고, SAP 표준 기능으로 커버되는 부분은 커스터마이징(설정, Configuration)을 통해 구현. 표준으로 안 되는 부분에 대해 개발 요건 정의서(기능 명세서, Functional Spec)를 작성.
  - ABAP 개발자: 기능 명세서를 받아 실제 프로그램(리포트, 인터페이스, 폼, 확장 로직 등)을 ABAP 언어로 구현하는 기술 명세(Technical Spec) 및 코딩 담당.
- 개발자라도 최소한의 업무 도메인 이해가 필수적이다. 예를 들어 FI(재무회계) 모듈 개발을 하려면 전표, 계정과목, 결산 프로세스 등 회계 지식이 어느 정도 필요하고, MM(자재관리)이라면 구매·재고 프로세스를, SD(영업)라면 수주·출하·과금 프로세스를 이해해야 정확한 개발이 가능하다.
- 대표 모듈
  - **FI(Financial Accounting)**: 재무회계
  - **CO(Controlling)**: 관리회계/원가관리
  - **MM(Materials Management)**: 자재관리(구매, 재고)
  - **SD(Sales and Distribution)**: 영업/유통
  - **PP(Production Planning)**: 생산계획
  - **HR/HCM(Human Capital Management)**: 인사

### 핵심 기술 스택
- **ABAP(Advanced Business Application Programming)**: SAP 전용 4세대 프로그래밍 언어(4GL). 절차적 프로그래밍 방식으로 시작했으나 이후 객체지향(ABAP OO)까지 지원하도록 확장되었고, 최근에는 ABAP Cloud라는 형태로 클라우드 개발 모델까지 진화하는 중.
- **개발 환경**
  - **SAP GUI + SE80**: 전통적인 ABAP Workbench. 온프레미스 ECC/S4HANA 개발에서 여전히 널리 쓰인다.
  - **ADT(ABAP Development Tools) for Eclipse**: Eclipse 기반의 최신 ABAP 개발 도구. 최신 프로젝트(특히 RAP 기반 개발)에서는 사실상 표준으로 자리잡음.
- **SAP HANA**: 컬럼 기반 인메모리 데이터베이스. 디스크 I/O 병목 없이 대량 데이터를 실시간으로 집계·분석할 수 있어 S/4HANA의 성능 기반이 된다.
- **최신 개발 트렌드**
  - **SAP BTP(Business Technology Platform)**: SAP의 클라우드 플랫폼으로, 확장 개발(Side-by-side Extension), 통합(Integration Suite), 데이터/분석, AI 서비스 등을 아우르는 통합 플랫폼. 기존 SAP 시스템을 직접 수정하지 않고 BTP 위에서 확장 앱을 개발하는 방식이 권장된다.
  - **RAP(RESTful ABAP Programming Model)**: ABAP Cloud의 핵심 개발 모델로, CDS 뷰 + Behavior Definition + Service Definition/Binding을 계층적으로 조합해 트랜잭션 처리가 가능한 Fiori 앱과 OData 서비스를 개발하는 표준 방식. 기존의 Classic 방식(Dynpro, Function Module 기반 BAPI 등)을 대체해 나가는 중.
  - **SAP Fiori / UI5(SAPUI5)**: SAP의 최신 사용자 경험(UX) 프레임워크. HTML5/JavaScript 기반의 UI5로 구현되며, Fiori Elements를 사용하면 CDS 뷰의 어노테이션만으로 리스트/오브젝트 페이지 UI를 자동 생성할 수 있다.
  - **CDS View(Core Data Services)**: HANA DB 계층에서 뷰를 정의하는 선언적 언어. 단순 SQL 뷰를 넘어, 비즈니스 의미(어노테이션)를 부여해 분석(Analytics), Fiori UI, RAP 비즈니스 오브젝트의 기반 데이터 모델로 활용된다.

### 주요 개발 업무 유형 (RICEFW)
SAP 프로젝트에서 표준 기능으로 해결이 안 되는 커스텀 개발 요건을 통칭해 **RICEFW**라고 부른다.
- **R (Report)**: 데이터 조회/집계/출력을 위한 커스텀 리포트 프로그램
- **I (Interface)**: 외부 시스템과의 연동 (IDoc, RFC, BAPI, OData, API 등 사용)
- **C (Conversion)**: 레거시 시스템에서 SAP로 데이터를 이관하는 데이터 마이그레이션(LSMW, BDC, LTMC 등 활용)
- **E (Enhancement)**: 표준 프로그램을 건드리지 않고 로직을 추가하는 확장 기법 — User Exit, BAdI(Business Add-In), Enhancement Point/Spot
- **F (Form)**: 출력물 양식 개발 — SAPscript, SmartForms, Adobe Forms
- **W (Workflow)**: 결재/승인 등 업무 프로세스를 자동화하는 SAP Business Workflow

이 외에도 표준 트랜잭션의 화면/필드/버튼 등을 커스터마이징(Customizing)하는 IMG(Implementation Guide) 설정 작업도 넓은 의미의 SAP 프로젝트 업무에 포함된다.

### 일반 개발자와의 차이점
- **도메인 지식 중심**: 순수 기술력보다 회계/물류/인사 등 업무 프로세스에 대한 이해가 개발 품질을 좌우하는 경우가 많다. 기능 명세서를 정확히 해석하려면 해당 업무 용어와 흐름을 알아야 한다.
- **폐쇄적 생태계와 라이선스 기반 환경**: 오픈소스 생태계와 달리 SAP 자체 라이선스 정책, SAP 표준 프로그램/네이밍 규칙, SAP 고유의 트랜잭션 코드(T-code) 체계를 따라야 한다. 커뮤니티 자료도 SAP Community, SAP Help Portal 등 SAP 자체 채널 의존도가 높다.
- **SI/컨설팅 중심 프로젝트 구조**: 대부분 SAP 프로젝트는 고객사(End User) - SI/컨설팅사 - 개인/협력사 개발자로 이어지는 다단계 도급 구조에서 진행되며, 프로젝트 단위(구축, 유지보수/AMS)로 계약되는 경우가 많아 일반 서비스 기업의 애자일 개발 문화와는 결이 다르다.
- **레거시와 최신 기술의 공존**: 여전히 다수의 프로젝트가 Classic ABAP(Dynpro, BDC 등) 기반이지만, 신규/전환 프로젝트에서는 RAP, Fiori, BTP 기반의 클라우드 지향 개발이 빠르게 늘고 있어 두 세계를 모두 이해해야 하는 과도기적 상황이다.

## 핵심 정리
- SAP ERP 개발자는 회계·물류·인사 등 기업 핵심 업무 프로세스를 다루는 SAP 시스템을 ABAP 언어로 커스터마이징/확장/연동하는 개발자다.
- 기능 컨설턴트가 정의한 요건(기능 명세서)을 바탕으로 RICEFW(Report, Interface, Conversion, Enhancement, Form, Workflow) 형태의 커스텀 개발을 수행한다.
- 최신 SAP 개발은 S/4HANA + CDS View + RAP + Fiori/UI5 + BTP 조합으로 이동하고 있으며, 이는 클라우드 네이티브 확장 개발(ABAP Cloud)로의 전환을 의미한다.
- 순수 기술 역량 외에 업무 도메인 지식, SAP 생태계에 대한 이해, SI/컨설팅 중심 프로젝트 구조에 대한 적응이 요구된다.

## 기술적 한계와 보완 전략
- **Classic ABAP의 확장성 한계**: User Exit/BAdI를 남용하면 표준 업그레이드 시 충돌(컨플릭트)이 자주 발생한다. → SAP는 "Clean Core" 전략을 통해 표준 시스템을 최대한 수정하지 않고, BTP 위에서 Side-by-side 확장을 하도록 권장한다.
- **성능 이슈**: 잘못 작성된 ABAP(특히 SELECT 문에서 Nested Loop, SELECT *  등)는 대량 데이터 처리 시 심각한 성능 저하를 유발한다. → SQL Trace(ST05), 코드 인스펙터(SCI), CDS View 기반 푸시다운(연산을 HANA DB로 위임) 등을 통해 최적화한다.
- **레거시-클라우드 전환 리스크**: ECC → S/4HANA 전환 시 기존 커스텀 코드(특히 Table 구조 변경이 있는 부분)에 대한 대규모 리모델링이 필요하다. → SAP Readiness Check, ATC(ABAP Test Cockpit)의 S/4HANA 변환 체크 등을 활용해 사전 영향도를 분석한다.
- **폐쇄적 생태계로 인한 학습 곡선**: 오픈소스 대비 학습 자료와 커뮤니티가 제한적이다. → SAP Learning Hub, SAP Community, openSAP(무료 온라인 강의) 등 공식 채널을 적극 활용한다.

## 키워드
- **SAP**: 전 세계 ERP 시장 점유율 1위의 독일 기업이자 그 제품군을 통칭하는 이름.
- **ERP**: 회계·인사·물류·생산 등 기업의 전 업무 프로세스와 데이터를 하나로 통합 관리하는 시스템/개념.
- **ABAP**: SAP 시스템 커스터마이징과 확장 개발에 사용되는 SAP 전용 프로그래밍 언어.
- **S/4HANA**: SAP HANA 인메모리 DB 기반의 차세대 SAP ERP 제품.
- **SAP HANA**: 컬럼 기반 인메모리 방식으로 대용량 데이터를 실시간 처리하는 SAP의 데이터베이스 플랫폼.
- **RICEFW**: SAP 프로젝트에서 표준 기능으로 해결되지 않는 커스텀 개발 요건을 분류하는 약어(Report, Interface, Conversion, Enhancement, Form, Workflow).
- **SAP Fiori**: SAP의 최신 사용자 경험(UX) 디자인 시스템 및 앱 프레임워크로, UI5 기술로 구현된다.
- **SAP BTP**: SAP의 클라우드 확장·통합·데이터/AI 플랫폼(Business Technology Platform)으로, Clean Core 전략의 핵심 인프라.
- **CDS View**: HANA DB 계층에서 비즈니스 의미를 가진 뷰를 선언적으로 정의하는 기술로, 분석/Fiori UI/RAP 비즈니스 오브젝트의 기반이 된다.
- **IDoc(Intermediate Document)**: SAP와 외부 시스템(또는 SAP 시스템 간) 데이터 교환을 위한 표준화된 문서 포맷/인터페이스 기술.
